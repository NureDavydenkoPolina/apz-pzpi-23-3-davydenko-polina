	Метою лабораторної роботи є розробка мобільного застосунку для платформи Android, який є частиною інформаційної системи SmartFood та взаємодіє з серверною частиною.

3 ОПИС ВИКОНАНОЇ РОБОТИ
	У ході виконання лабораторної роботи було розроблено мобільний застосунок SmartFood для операційної системи Android з використанням мови Kotlin та фреймворку Jetpack Compose.
	На початковому етапі було створено проєкт у середовищі Android Studio та налаштовано базову структуру застосунку. Для реалізації взаємодії з серверною частиною було використано бібліотеку Retrofit, за допомогою якої налаштовано обробку HTTP-запитів до REST API. Було реалізовано отримання списку страв із сервера та їх відображення у вигляді списку за допомогою компонента LazyColumn. Для представлення даних створено модель Dish, яка використовується для відображення меню.
	Далі реалізовано механізм створення замовлення. При першому додаванні страви формується нове замовлення на сервері, після чого всі наступні страви додаються до нього. Ідентифікатор замовлення зберігається на стороні клієнта. Було створено окремий екран для перегляду замовлення, де відображається список обраних страв, їх кількість та загальна вартість. Дані завантажуються з сервера за допомогою відповідних API-запитів.
	Реалізовано функціонал видалення позицій із замовлення. Після видалення відбувається повторне завантаження даних, що забезпечує актуальність відображеної інформації. Також додано можливість відправлення замовлення, після чого редагування стає недоступним, а користувач може створити нове замовлення. Для покращення користувацького досвіду було реалізовано вибір номера столика через випадаючий список. 
	Було проведено кастомізацію інтерфейсу застосунку - змінено кольорову тему, додано інтерактивні елементи.
	У процесі розробки було виправлено ряд помилок, пов’язаних із асинхронною обробкою даних, оновленням стану інтерфейсу та коректним обчисленням загальної вартості замовлення.
	Діаграма прецедентів відображає основні сценарії взаємодії користувача з мобільним застосунком SmartFood. Користувач може обрати столик, переглянути меню, додати або видалити страви із замовлення, переглянути замовлення та відправити його (рисунок 1). 

Рисунок 1 - UML діаграма прецедентів (Use Case Diagram)

	Діаграма компонент відображає загальну архітектуру системи. Мобільний застосунок складається з інтерфейсу користувача та мережевого шару, реалізованого за допомогою Retrofit. Застосунок взаємодіє з сервером через HTTP-запити у форматі JSON. Серверна частина, реалізована на Flask, обробляє запити та виконує операції з базою даних SQL Server (рисунок 2).

Рисунок 2 - UML діаграма компонент (Component Diagram)

	Діаграма пакетів показує логічну структуру мобільного застосунку. Код поділений на основні пакети: ui, network та model. Пакет ui містить підпакет screens, у якому знаходяться екрани застосунку. Пакет network відповідає за взаємодію з сервером, а model містить структури даних. Залежності між пакетами зображені у вигляді пунктирних стрілок (рисунок 3).


Рисунок 3 - UML діаграма пакетів (Package Diagram)

	Діаграма діяльності відображає послідовність дій користувача та системи під час роботи із застосунком. Користувач відкриває застосунок, обирає столик і переглядає меню. Далі він може додавати страви до замовлення. Якщо замовлення ще не створене, система створює його та зберігає ідентифікатор. Користувач може змінювати замовлення, зокрема видаляти страви або додавати нові. Після завершення редагування замовлення відправляється на сервер (рисунок 4).
