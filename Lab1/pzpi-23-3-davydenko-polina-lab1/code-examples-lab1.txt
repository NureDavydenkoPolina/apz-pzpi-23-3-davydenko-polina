Отримана відповідь:
3.2 Scope of Subsequent Releases
У наступних версіях системи SmartFood планується інтеграція технологій штучного інтелекту з метою підвищення ефективності роботи системи, покращення користувацького досвіду та розширення аналітичних можливостей.
Застосування штучного інтелекту
Штучний інтелект може бути використаний у системі SmartFood у таких напрямках:
Рекомендаційна система — аналіз попередніх замовлень користувачів для формування персоналізованих рекомендацій страв;
Прогнозування попиту — визначення популярних страв у певні години або дні для оптимізації роботи кухні та закупівель;
Аналіз ефективності роботи персоналу — виявлення затримок у обробці замовлень та оцінка продуктивності;
Інтелектуальний чат-бот — автоматизація взаємодії з клієнтами (відповіді на питання, допомога у виборі страв);
Виявлення аномалій — пошук нетипових ситуацій (наприклад, різке падіння продажів або помилки в замовленнях).
Збирання даних
Для реалізації функцій штучного інтелекту система може збирати такі дані:
історію замовлень (склад замовлення, кількість, час створення);
популярність страв;
час обробки замовлень на різних етапах (created → cooking → ready → delivered);
дії користувачів у системі (вибір страв, додавання до кошика, скасування);
навантаження на систему (кількість замовлень у певні періоди).
Збирання даних здійснюється автоматично через серверну частину системи, яка зберігає інформацію у базі даних. Додатково можуть використовуватися журнали (logs) для фіксації подій і поведінки користувачів.
Навчання та використання моделей
Для інтеграції штучного інтелекту доцільно використовувати комбінований підхід:
готові API-сервіси ШІ — для швидкої реалізації функцій, таких як чат-бот або рекомендації;
донавчання моделей — використання зібраних даних системи для покращення точності рекомендацій;
власні моделі — для задач прогнозування попиту та аналітики, де потрібна специфічна логіка системи.
На початкових етапах доцільно використовувати готові AI-сервіси, оскільки це дозволяє швидко інтегрувати інтелектуальні функції без значних витрат ресурсів. У подальшому, із накопиченням достатньої кількості даних, можливий перехід до навчання власних моделей або донавчання існуючих.

3.3 Limitations and Exclusions
Незважаючи на реалізацію основного функціоналу системи SmartFood, поточна версія має низку обмежень, зумовлених вибором архітектури, технологій та обсягом початкового релізу.
Обмеження системи
Відсутність мобільного застосунку
У поточній версії система використовує вебінтерфейс та IoT-клієнти. Повноцінний мобільний застосунок не реалізовано, що може обмежувати зручність використання для деяких користувачів.
IoT-клієнти реалізовані у вигляді симуляції
Table IoT та Kitchen IoT працюють як програмні клієнти, а не фізичні пристрої, що обмежує можливість тестування системи в реальних умовах експлуатації.
Обмежена масштабованість
Система розгортається як один сервер без горизонтального масштабування, що може створювати проблеми при високому навантаженні.
Обмежена реалізація оплати
У системі відсутня повноцінна інтеграція з платіжними сервісами, що обмежує можливість автоматичної обробки транзакцій.
Залежність від мережевого з’єднання
Усі компоненти системи взаємодіють через мережу, тому відсутність стабільного інтернет-з’єднання унеможливлює роботу системи.
Виключений функціонал
У межах початкового релізу свідомо не було реалізовано деякі функції, які можуть бути додані у майбутніх версіях:
Офлайн-режим роботи
Не реалізовано через складність синхронізації даних між клієнтами та сервером після відновлення з’єднання.
Повноцінний мобільний застосунок
Виключено з першого релізу для зменшення складності розробки та концентрації на серверній логіці та основному функціоналі.
Інтеграція з зовнішніми платіжними системами
Вимагає додаткових заходів безпеки та відповідності фінансовим стандартам, тому перенесена на наступні етапи.
Розширені AI-модулі
Функції штучного інтелекту (рекомендації, прогнозування) не включено до початкової версії через необхідність накопичення достатнього обсягу даних.
Підтримка великої кількості закладів (multi-tenant система)
Поточна реалізація орієнтована на один заклад, а підтримка мереж ресторанів потребує додаткової архітектури.
